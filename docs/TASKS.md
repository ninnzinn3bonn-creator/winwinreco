# GIJIRO 作業バックログ (セッション間共有)

このファイルは「**未完のまま次のセッションへ持ち越したいタスク**」を 1 箇所に集約するためのものです。
別の Claude セッションで作業を再開するときは、まず本ファイルを読み、優先順位順に着手してください。

## 運用ルール

1. **新セッションを開始したら** 最初に本ファイルを `Read` してください。`PROGRESS.md` (履歴ログ) と `docs/ARCHITECTURE.md` (設計規約) も併読すると文脈が揃います。
2. **タスクに着手するとき** は本ファイルの該当タスクの状態を `IN PROGRESS` に書き換えるか、TaskCreate ツールで同名タスクを再登録してから始めてください。
3. **タスクが完了したら**:
   - 本ファイルから該当タスクのブロックを削除
   - 同等の作業実績を `PROGRESS.md` に節として追記 (`## NN. xxx (YYYY-MM-DD)` 形式)
   - 関連するアーキテクチャ規約があれば `docs/ARCHITECTURE.md` に追記
4. **新たなタスクが見つかったとき** は本ファイルの末尾に追加してください。フォーマットは既存ブロックに合わせます。
5. **行番号** は実装の手がかりとして書かれています。コード変更で番号がずれるのは前提なので、シンボル名 (関数名・ID・クラス名) を最終的な照合キーにしてください。

## タスクのフォーマット

各タスクは次の 7 つのフィールドを持ちます。

```
### [ID] タイトル
**優先度**: high | medium | low
**対象ファイル**: 修正が予想される主なファイル
**現状の挙動**: 何が起きているか
**期待する挙動**: あるべき姿
**実装ステップ**: 1. 〜 2. 〜 のチェックリスト
**検証手順**: 自動テストまたは手動確認の手順
**完了条件**: これが満たされたら done
```

### L シリーズ — 長時間会議向けのチャンキング戦略 (L9〜L11)

**背景**: L1〜L4 で議事録の Map-Reduce パイプラインを実装済み。L5 以降は追加の改善。
**既定パラメータ**: チャンク窓10分、適応トリガー8000トークンor25分、オーバーラップ30秒、並列度2。


#### [L9] チャンク結果を DB に保存して部分再生成可能に
**優先度**: low (L4 完了後)
**対象ファイル**: `src/backend/repo/db.js`, 新規 `src/backend/repo/chunk-repo.js`, `src/backend/app.js`
**現状の挙動**: minutes は `rooms.minutes_text` に最終結果のみ保存。
**期待する挙動**: チャンク単位の中間結果を `room_chunks` テーブルに保存 (`room_id`, `chunk_index`, `start_ts`, `end_ts`, `result_text`, `status`)。再生成時に未失敗チャンクをスキップ。
**実装ステップ**:
1. `room_chunks` テーブルを `ensureColumn` 同等のマイグレーションで追加。
2. Map 段で chunk-repo に upsert。
3. 再生成 API: `POST /rooms/:id/regenerate-chunk/:index` を追加 (ホスト限定)。
4. フロント: 議事録の各セクション右肩に「再生成」ボタンを追加。
**検証手順**:
- 失敗したチャンクだけを再生成し、議事録が更新される手動シナリオ。
**完了条件**: 部分再生成が動く。

#### [L10] ARCHITECTURE.md と PROGRESS.md の更新
**優先度**: low (実装完了後)
**対象ファイル**: `docs/ARCHITECTURE.md`, `PROGRESS.md`
**実装ステップ**:
1. ARCHITECTURE.md に「長時間会議のチャンキング戦略」セクションを追加。
2. PROGRESS.md に `## NN. 長時間会議対応のチャンキング実装 (YYYY-MM-DD)` として実装履歴を残す。
3. `docs/TASKS.md` から L1〜L9 を削除。
**完了条件**: 規約と履歴が永続化される。

#### [L11] 将来検討: 会議中のストリーミング生成 (記録のみ)
**優先度**: low (将来の最適化)
**対象ファイル**: 検討ドキュメントのみ
**メモ**: 会議中に N 分ごとに「現時点までの議事録」を背景生成して `rooms.streaming_minutes_text` に保存。終了時は最後のチャンクだけ生成して merge。
- 利点: 終了後の待ち時間 1 桁秒。
- 欠点: 永続化と冪等性、話題が後から戻ってきた場合の上書きルール、コストが増える。
- 現時点では L1〜L10 で十分な体感改善が得られると見込み、L11 は計測してから判断。
