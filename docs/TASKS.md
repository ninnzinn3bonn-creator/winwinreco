# GIJIRO 作業バックログ (セッション間共有)

このファイルは「**未完のまま次のセッションへ持ち越したいタスク**」を 1 箇所に集約するためのものです。
別の Claude セッションで作業を再開するときは、まず本ファイルを読み、優先順位順に着手してください。

## 運用ルール

1. **新セッションを開始したら** 最初に本ファイルを `Read` してください。`PROGRESS.md` (履歴ログ) と `docs/ARCHITECTURE.md` (設計規約) も併読すると文脈が揃います。
2. **タスクに着手するとき** は本ファイルの該当タスクの状態を `IN PROGRESS` に書き換えるか、TaskCreate ツールで同名タスクを再登録してから始めてください。
3. **タスクが完了したら**:
   - 本ファイルから該当タスクのブロックを削除
   - 同等の作業実績を `PROGRESS.md` に節として追記 (`## NN. xxx (YYYY-MM-DD)` 形式)
   - 関連するアーキテクチャ規約があれば `docs/ARCHITECTURE.md` に追記
4. **新たなタスクが見つかったとき** は本ファイルの末尾に追加してください。フォーマットは既存ブロックに合わせます。
5. **行番号** は実装の手がかりとして書かれています。コード変更で番号がずれるのは前提なので、シンボル名 (関数名・ID・クラス名) を最終的な照合キーにしてください。

## タスクのフォーマット

各タスクは次の 7 つのフィールドを持ちます。

```
### [ID] タイトル
**優先度**: high | medium | low
**対象ファイル**: 修正が予想される主なファイル
**現状の挙動**: 何が起きているか
**期待する挙動**: あるべき姿
**実装ステップ**: 1. 〜 2. 〜 のチェックリスト
**検証手順**: 自動テストまたは手動確認の手順
**完了条件**: これが満たされたら done
```

### [OPS-2] API キーローテーション
**優先度**: medium
**対象ファイル**: GCP Secret Manager
**現状の挙動**: §48 のトラブルシュート時にチャットへ API キーの平文出力が一度残った経緯あり。
**期待する挙動**: 4 シークレット (Gemini / Google / Groq / ElevenLabs) を各プロバイダーのダッシュボードで再発行 → Secret Manager の `versions add` で更新 → Cloud Run を新リビジョンへ。
**実装ステップ**:
1. 各 API ダッシュボードでキー再発行。
2. `gcloud secrets versions add <secret-id> --data-file=-` で新バージョンを登録。
3. Cloud Run は `--set-secrets=...:latest` 指定なので次回デプロイ or 手動 `gcloud run services update --update-secrets=...` で自動的に新版へ。
**完了条件**: 旧キーが各プロバイダー側で `disabled` になっており、本番が新キーで稼働している。
